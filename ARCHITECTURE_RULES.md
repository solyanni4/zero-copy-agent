# Архитектурные инварианты и правила zero-copy-agent (ZCA)

Данный документ фиксирует обязательные системные инварианты кодовой базы `zero-copy-agent`. Все доработки, рефакторинг и новые модули обязаны строго соблюдать эти правила.

---

### 1. Единая резолюция прокси (`resolve_http_proxy`)
* Любое создание HTTP-клиента (`httpx.AsyncClient`, `httpx.Client`) или сетевого подключения обязано использовать централизованную функцию `resolve_http_proxy(proxy_setting: Optional[str] = None) -> Optional[str]`.
* Запрещено передавать в параметр `proxy` библиотеки `httpx` служебные строки `"direct"`, `"auto"`, `"none"` или пустые строки `""`. Функция возвращает либо валидный URL прокси (`http://...`, `https://...`, `socks5://...`), либо `None` для прямого подключения.
* Запрещено дублировать эвристику `detect_proxy()` в разных модулях. Все компоненты (`orchestrator`, `providers`, `browser_session`, `main`) используют единый источник истины.

### 2. Жёсткая фиксация выбранной модели (UI / DAG / Cascade)
* Ручной выбор модели пользователем в UI, пресетах или DAG жестко фиксирует выбранную модель.
* Запрещено скрытое переключение в Мульти-Архитектор, дефолтную модель или локальную модель в обход прямого выбора пользователя.
* Запрещены захардкоженные модели в цепочках фоллбэков (например, принудительный откат на `gemini-4-neon` или `gemini-advanced` вместо модели из активного аккаунта пользователя).
* В оркестратор и провайдеры передаётся полная история сообщений диалога без обрезания контекста предыдущих ходов пользователя и ассистента.

### 3. Защита процесса, порта 8000 и атомарность сохранения на Windows
* Строго один активный процесс-владелец порта `8000`. При запуске проверяется доступность порта, исключая запуск зомби-процессов.
* При вызове `/v1/app/quit` и остановке приложения выполняется корректный graceful shutdown: закрытие ASGI-сервера, завершение WebSocket-сессий Chrome Bridge, закрытие сетевых сокетов и соединения с БД SQLite (`solutions_db`).
* Функция атомарного сохранения (`atomic_save`) обязана использовать уникальные имена временных файлов (через `secrets.token_hex(4)` или `uuid4()`), чтобы предотвратить блокировки и ошибки `PermissionError` при конкурентной перезаписи файлов на Windows.
* Запрещен мёртвый и дублирующий код (например, повторные определения `main()` в десктопных модулях).

### 4. Асинхронность и чистота I/O (No Blocking I/O in Async)
* Запрещен блокирующий синхронный I/O (`open()`, тяжелые дисковые операции, синхронные запросы SQLite, вызовы субпроцессов) внутри корутин `async def` без явной обёртки в `asyncio.to_thread()`.
* Единый согласованный API для трекинга активности (`ActivityTracker`).
* Единый синглтон для квотного меша (`QuotaMesh` / `mesh`).

### 5. Стабильность Chrome Bridge и тайм-ауты потока
* Таймаут первого токена (`45s`) в `ChromeBridgeManager` сбрасывается исключительно при получении реального текстового чанка (`type="chunk"`) или завершающего маркера (`type="done"`), но ни в коем случае не служебными пульсами статуса.
* Служебные статусы `stage="generating"` передают структурированную телеметрию (`responsesCount`, `lastLen`, `isGenerating`, `matchedSelector`) без сброса таймера ожидания первого чанка.

### 6. Безопасность UI и согласованность пресетов
* При сохранении пресета бэкенд гарантирует автогенерацию уникального `id`, если идентификатор не был явно передан клиентом.
* Обязательное экранирование всего динамического пользовательского текста через функцию `escapeHtml()` на фронтенде во избежание XSS при рендеринге названий пресетов, идентификаторов моделей и логов задач.
